# Keep a write across offline and reload

For an engine-owned collection, the DataEngine commit queue keeps a submitted request and its exact identity across editor unmount, reload and offline time. A manual form's unsent typing belongs to `useDataForm` and its durable stage. Use the public hooks in `frontend/app/data-engine/react.client.tsx`; do not add another queue.

## How

- `useDataDocument.update` persists local editing immediately; `commit` or `save` captures a submitted command in the shared queue. Closing an autosaving editor flushes savable typing. A submitted chain can continue after navigation or restart; unresolved branches and unsent manual drafts require explicit recovery.
- Native document Save/commit captures the canonical request and its exact submitted-generation checkpoint in one IndexedDB transaction (`commits.client.ts` + `checkpointStorage.client.ts`). The same validator and reference collector also serve ordinary checkpoint writes. While submitted captures wait, `EditorController.persist` cannot write a newer RAM draft ahead of its request. Each capture uses the actual stored identity, including deduplication winners; it does not absorb later unsent typing. Deletion registers this capture before awaiting local editing. A no-op still finishes checkpoint persistence. Custom document-only stores without `createWithCheckpoint` keep the request-first compatibility path; they do not provide the native atomic guarantee.
- To verify this boundary, interrupt after the native checkpoint transaction commits but before its page completion callback. Reopen with a fresh editor identity, then retry delivery: the exact submitted value/deletion must continue without a recovery click. Cover one edit, rapid edits, later unsent typing, failed capture and retry, and rollback of request + identity + checkpoint together. Never simulate the boundary by holding the transaction lock until the callback: a finished native transaction has already released its locks. No transaction can preserve page memory that closed before durable capture began.
- `useDataForm.begin/update` pins and durably stores unsent manual typing without sending it; `save` captures the chosen draft. Use its status, recovery identity and `useRecoveryDiscovery` for reload recovery.
- A Save/commit resolves after its local request is durable, before server acknowledgement. `DataEngine.prepareCommitsInBackground` schedules the existing runner through owner-scoped background failure reporting. Never await post-capture `CommitQueue.drain(false)` from an interactive Save: a shared runner may already be delivering or be upgraded to delivery after it started. Explicit `engine.retry()` still awaits the queue. This boundary keeps sequential one-shot service-order edits captured before navigation; collections then show the saved chain at once. It does not make pre-capture page memory durable.
- For exact backup cleanup, opt into `useDocumentActions.submit` (see `write-a-document-field.md`). Its stable request receipt separates durable local capture from `persistence`, which resolves only for the complete accepted write. A note adapter always reports its local handoff as queued; its actual snapshot/revision, Saved marker and audio cleanup follow that exact persistence result. Its extra text backup can transfer to the captured request through the identity bridge below. A failed later editor-checkpoint projection is reported/repaired independently and cannot revoke an already captured request receipt. A no-op needs an equal confirmed copy and no unresolved same-resource request.
- A queued note handoff stays silent until its exact receipt later confirms the whole write. At that point confirm its captured payload and restore the Saved marker; retain the existing revision guard and current-text comparison so an older acknowledgement cannot label newer words as saved. Never rewind a newer local baseline from the create receipt callback.
- A server-accepted request remains the durable accepted copy while its separate snapshot-cache write fails. The ACK CAS writes an `accepted-cache` reference in the existing state transaction; checkpoint projection cleanup (including older writers) cannot remove that purpose. `DataEngine.completeAcceptedProjection` releases it through the existing collector only after every acknowledged participant snapshot is durably covered by the shared cache. Keep checkpoint/manual/capture references independent; cache success does not erase later unsent words. An old bundle's already-collected payload cannot be reconstructed from a missing request.
- An editable opening and a committed-participant read use `DataEngine.knownSnapshot`: load durable requests before reading cache, hydrate the existing revision-guarded map, then fold only actual matching-owner/resource acknowledged snapshots using `canReplaceSnapshot`. Never promote queued/conflict/refused/cancelled intent or weaken generation/tombstone guards. `snapshotIdentity.ts` reuses each collection's `getResourcePolicy` (users own their document id; other policies choose their owner field); do not hardcode userId for every collection. The read-only `peekCached` fallback deliberately remains independent of potentially silent editor-state storage. Regressions: `acceptedSnapshotBaseline.test.ts`.
- Inside the engine, publish request records through the existing `DataEngine.rememberCommit` revision rule: an older list result cannot replace a newer event record for the same request. All five public collection paths use `DataEngine.projectCollection`: preserve the entire source `CollectionState` and derive only `documents` from the current request map. Direct read/refresh still await and hydrate the durable list, then apply this same projection; an old empty request list must not hide a later captured resource. Keep owner/generation and opening-lifetime checks at the caller. This is read-only in-memory presentation; do not reinterpret queued work as accepted, resurrect collected durable identities, or change durable retention and membership pin ownership.
- Preserve the operation identity when retrying unknown delivery. A locally completed action proves durable ownership on this device; server acceptance requires the matching acknowledged status and confirmed copy. Render `DataSyncStatus` and collection presentation rather than a false success toast.
- A toast Undo may outlive its screen: capture the original action through the live public editor before navigation, then use `useDocumentActions.commit(resource, updater)` for its entity-bound reversal. `useCouncilDataDocument.finishCouncil` returns this capability without retaining a council snapshot. It commits Finish locally; if the held draft already exists after a capture failure, `document.save()` retries it unchanged. `components/council/councilActionNotice.ts` owns pending/failed presentation, duplicate-tap guards, neutral eight-second Undo and route handoff. Its conduct view stays open until capture/navigation completes or the person retries. The canonical predecessor and decision guards stay in place; no feature queue or closed-editor revival.
- A mounted editor may follow an ordinary queued successor only when its predecessor is already the editor's unique known pending tip. The controller first uses the existing submittedWorkCheckpoint rule over the durable queue: known competing branches stay separate, independent of event order. `DataSession.adoptSubmittedSuccessor` merges the submitted delta over that tip while preserving private sibling words; unrelated branches, conflicting private fields, atomic work and unobserved ancestors stay isolated. Register the adopted request at its local generation; advance once more for private unsent words so autosave still owns only their remainder. A request-scoped stored-version choice rebases from the exact decided submitted value via the existing refusal merge, retaining later words without recapturing the cancelled fields. Local projection never advances the confirmed snapshot.
- A clean editor may also show one submitted root update from the canonical `ACTION_SLOT` when the request has no predecessor, its full baseline equals this editor's confirmed copy, and it is the unique durable chain. `EditorController` reloads the current request and uses `assertCommitCapture`, not a stale event's mutable delivery state. Exclude retained/manual scopes, root create/delete, prepared relation commands and an initialized working copy that has already diverged. Ordinary screen roots remain separate: adopting them can falsely assign recovery decisions to another screen (`screenDraftAnsweredAfterLeaving.test.tsx`). Known forks are rejected at the queue snapshot; a future sibling is not predicted.
- Scratch delete Undo restores one absent note through `useDocumentActions.commit` for the original sermon and awaits local capture. Existing note identity keeps its newer words; an absent note retains exact fields, including whitespace and provenance. Ordinary adds/edits still use the live Scratch editor. The toast owns one in-flight restore and reports real capture failure with the existing localized save error; no stale scratch-array replacement or second queue.
- Do not put `recoverableWrite`, React Query paused mutations or a second outbox on an engine feature. Legacy client writers of engine collections refuse with `data-engine-required`.

## Legacy paths (unconverted collections only)

These compatibility paths are not templates for new features. Their contract is `frontend/docs/recoverable-writes.md`.

- Know who owns the write once the person lets go:
  - A React Query mutation offline pauses and is persisted to IndexedDB (only paused and failed ones: `shouldDehydrateMutation` in `frontend/app/providers/QueryProvider.tsx`), then resumed by `resumePausedMutations`. After a reload the `useMutation` closure is gone, so resume is a silent no-op unless `registerOfflineMutationDefaults` has `setMutationDefaults(key, { mutationFn })` for that key. Share the key constants (`GROUP_MUTATION_KEYS`, `PRAYER_MUTATION_KEYS`…) between the hook and the default.
  - A guarded field write (`conflictSafeUpdate`) offline becomes an outbox entry: patch, aggregate, the revision and field values it was built from, in localStorage. `replayOutbox` replays it through the same compare-and-set; if the server moved on, the entry is marked `conflicted` and keeps its text.
  - A plain client-SDK write offline sits in Firestore's own persistent queue.
- Variables must replay on their own: no closure state. Mint ids with `newClientId()` (`frontend/app/utils/clientId.ts`) and action-time timestamps BEFORE `mutate()` and put them in the variables — `addUpdate` in `frontend/app/hooks/usePrayerRequests.ts` carries `updateId` and `createdAt`. Minted inside the mutation function, a resumed or retried run makes new children (duplicates) and stamps replay time over action time. `expectedRevision` rides in the variables too; a replay that drops it is an unguarded overwrite.
- A create carries its client id, so a replayed create upserts the same document instead of a second one.
- Return right after the optimistic cache update. Never `await` the SDK write on an interactive path: offline it waits for the server acknowledgement and never resolves, so a modal, select or dropdown stays "saving" until reconnect (`useSeriesMembership`). The editor awaits acceptance, not persistence: `awaitAcceptance(submission, onLateFailure)`. `queuedMutation` accepts once the queue owns the write (after one tick, so an already failed write still rejects); `persistedWrite` accepts when the server has it and treats `OfflineQueuedError` as `queued`.
- Say "saved" only through `announceIfPersisted`; `queued` and `skipped` stay silent by construction.
- A refusal that arrives later is reported by the hook's `useWriteRecovery` descriptor, which carries the person's text. Its `owns` check is mandatory: failed mutations persist in a cache shared by every account on the device.
- Share-link revocation has no authored text but still needs recovery after restart. The delete descriptor opts into `retainWithoutTextAcrossSessions`; both live and resumed mutations use `revokeShareLinkMutationOptions` from `utils/studyNoteShareLinkWrites.ts`. Its stable mutation key retains unresolved failures beyond ordinary collection, and an acknowledged DELETE retires only that owner's exact capability failures. Existing successful records are pruned; other targets, owners and paused work remain. Patch a known list, never invent an empty one; mark it stale without immediately replacing the ACK with another list read. A cached empty list, remount, retry failure or old response is not completion proof. Creation and ordinary textless switches keep their old-session silence. Do not add another journal.
- Retry intent, local state and conflict metadata survive together. A retry kept in a component ref or closure dies with a reload, redirect or auth bounce.
- Residual risk: an online mutation still in flight is not persisted, so closing the tab at that moment loses it. For expensive text add a durable draft (`frontend/app/utils/durableDraft.ts`).

## Durable draft of an editor (`useDurableDraft`)

The note editor (and the plan's cells, `usePlanTextDraft`) keeps unsaved typing in localStorage (`frontend/app/utils/durableDraft.ts`): typing keeps a safe copy until an exact canonical request owns it, or a legacy writer confirms it. Historical copies with no proven transfer stay available as explicit recovery, never automatic replacement.

- Key the mounted note editor by owner and logical opening through `useNewNoteOpening`. Keep its independent writer identity stable through native URL adoption. Departure flushes the last keystrokes to that writer address; a new account never inherits its React editor or backup.
- A departing flush must not replace another unfinished opening of the same note. `draftKey(owner, document, aggregate, writerId)` uses the shared versioned address module; v1 copies remain readable. The writer ID is distinct from the reserved creation ID and from the canonical request token. Cleanup or delivery time is not author chronology. Never solve this by dropping the final keystroke, clearing on logout, or hiding an overwritten copy in an archive.
- Never clear a draft because the key changed, the text equals what the screen opened with, or the slot looks empty. A draft leaves only by exact match (`clearDraftIfMatches`): `markSaved` when the server confirmed that text, the person's "reject" of the offered text, and the editor itself when the person types back to the confirmed text — then only the draft this editor wrote.
- For note autosave, `saveDraft(key, value, creationTargetId, true)` mints an opaque payload identity in the existing ordinary value write. `prepareDraftCapture` only reads that exact record and encodes identity/address/resource into the public `submit(..., { captureScope })` option; never attach metadata through a second read-modify-write of the shared text. A same-value flush preserves the identity, including owned adoption to the actual note address; changed words drop or replace it.
- Existing CommitRequest/capture-reference rows are atomically stored together and retain the full words across native transaction completion before its JavaScript callback. The owner-scoped workspace connector in `utils/draftCaptureRecovery.client.ts` reads actual retained captures through the public engine port. It validates owner/resource/address, compares identity and current value before retiring a local copy, notifies the mounted draft hook, and releases only that exact capture reference through the shared collector. A crash after local removal is replayable; strict reads of the validated source address and its one adopted note address are required before releasing an orphan hold. Read/parse/removal failures at those addresses defer cleanup; unrelated malformed drafts cannot retain every captured request. Missing request never means accepted.
- Legacy unbound copies, failed identity writes, and metadata stripped by an immutable older bundle remain unknown, with neutral comparison/recovery text. Never infer their outcome from equal text, clocks, connectivity or a cached server response. Exact server ACK still owns Saved/audio confirmation. The original two-store limit was reproduced by native reload while autosave was in flight; callback-only cleanup was rejected by holding the actual IndexedDB oncomplete handler after commit. Pending/refused canonical words remain in the existing queue/recovery rather than a second ledger.


### Local draft edit chronology

`utils/durableDraft.ts` owns the optional `editedAt` metadata, `savedAt` storage time, timestamp comparison and capture identity. `useDurableDraft` remembers a new clock only when canonical serialized editor content changes. Equal immutable values, owner availability, a document-ID handoff, debounce and page departure do not create another edit. A timer carries its own value/time pair; an immediate departure reads the current pair. Known older writes cannot replace a strictly later known edit at the same physical address.

The browser clock is `performance.timeOrigin + performance.now()`, with `Date.now()` as a compatibility fallback and monotonic advancement beyond this opening's observed same-address edit. This is local ordering support, never proof of cross-device or server chronology. Old records remain readable with `savedAt` as a presentation fallback. Equal edit times use a stable physical-key order rather than later flush time; retain independent choices. Comment legacy-door and note current/precreate unions use the same comparator after merging.

Immediate note-create backups and `prepareNoteDraftCapture` carry the opening's original edit time. A same-payload canonical refresh keeps that time; a new equal-word edit drops the earlier capture token. The submitted callback and retired-copy event carry their edit identity, so an old A capture cannot claim A typed again after B. Accepted text ends the old unconfirmed ownership; it cannot later remove another opening's equal words when adopting a delivered baseline. The canonical queue and server ACK keep their existing owners. A module-level backup failure is not by itself proof of user-visible loss: inspect the immediate backup and retained canonical request too.

### The initial recovery question

`useDraftQuestion` in `hooks/useDurableDraft.ts` owns the first decision for one owner/resource/opening. A real Restore or confirmed Discard answers it; remaining independent variants stay readable without relocking that opening. Changing identity resets the question, and a stale callback cannot answer the next opening, even A -> B -> A. Read-only data remains read-only.

`useSettleShownDraft` follows each selected physical `recoveredKey`, not just one equality boolean. It calls `settleRecovered` to hide equal shown words; equality with unconfirmed working text never adopts that independent source. Only equality with the complete confirmed baseline retains the existing settled-copy cleanup through exact source-record checks. `acceptRecovered` is the explicit selected-source adoption path. Audio-only metadata adoption does not answer another authored-text question. Tests: shared hook, CommentDialog, note page and paired plan read-only/recovery suites.

### Comment draft recovery

`utils/commentDrafts.ts` owns the logical comment door, payload validation, restored reference identity and historical optional-title representation. The window uses the canonical `useDurableDraft` with one stable `newClientId` writer per opening; `draftAddress` owns escaped physical v2 addresses. A decoded scoped address proves the original opening independently of its movable reference contents. Older Bible doors put colons in a v1 document ID: read that exact legacy key only when the owner and retained reference match the requested door; do not change the shared v1 grammar, whose aggregate may itself contain colons. Restore adopts the retained reference ID while preserving the opening coordinates; `useCommentPlace` owns the chosen move and PutBack. Preserve an absent historical empty title for exact retirement. Returning to the confirmed baseline releases only an explicitly adopted source through the existing exact `sourceRecord` comparison, even before this writer first debounces. Merely opening another window, equal unconfirmed working words in an unselected copy, or a replacement record never authorizes deleting that source. The complete confirmed-baseline exception is described above; it is not a comparison with current restored typing. The generic equality/retirement mechanism remains the owner of deletion.

### Precreate note ownership

A new note reserves its canonical `newClientId` before typing. `new~<creationId>` is its logical precreate address; each mounted writer keeps a separate physical backup there. The payload and any refused storage debt carry `creationTargetId`; `createNote(input, { id })` submits that same resource. Adoption moves only this writer to the actual note address. `moveDraft` checks the expected creation identity; canonical capture and exact server acceptance retire the matching payload. A confirmed creation ID proves a destination existed, not that every unfinished copy was submitted. It must never clear unknown precreate words. A known tombstone redirects retained text to a read-only missing-record view; it never recreates the note.

Before a note create, synchronously refresh this writer's exact precreate backup with the complete submitted payload. Immediate dictation can beat the250ms typing debounce. Refresh only an absent source or one whose creation tag matches the reserved ID; a legacy source from another writer is not adopted by that tag alone. Move only after `saveDraft` succeeds. On refusal keep the original copy and existing warning while the canonical queue can still capture current words. After exact full-write acceptance, an unchanged prior copy of this same scoped writer can be retired from its pre-submit snapshot; compare immediately so later words survive. Unknown v1 sources stay until an explicit choice or exact content proof. Tests: `useNoteAutoSave.test.tsx`, `placeholderDraftOwnership.test.tsx` and the note-page dictation recovery scenarios.

The shared address parser and `findDraftCopies` discover legacy and scoped records without mixing owner, document or aggregate. `utils/newNoteDrafts.ts` maps a valid precreate source to its actual note and validates all payloads before display. The Studies list shows each unfinished copy with its exact key in the React row and continuation URL. Resume URLs carry `draft`, `draftOwner` and, for a selected copy, `draftCopy`; these are navigation hints, never authorization. Select only a key actually found among this owner's valid resource copies. A missing-source `/new` bookmark starts independently. Reflecting a reserved URL before the first backup and adopting a native created URL retain the same mounted opening. `useResolvedUid` waits for real auth restoration, including anonymous sessions, without a storage fallback.

A surviving precreate source can resolve an already projected or confirmed destination, so resuming it must not create the resource twice. `findNoteDraftCopies` exposes that source beside actual-ID copies; every known alternative remains readable/selectable through the note's recovery surface. If the destination is absent, `RecordUnavailable` keeps the copies readable/copyable without Restore or autosave. The list links a known created-but-unrepresented destination to its actual route. Collection IDs alone never retire text. Canonical capture keeps its existing exact identity bridge and one queue. Fresh audio uses the reserved creation ID; restoring audio-only default-note metadata adopts source links, while authored question/type or text remains explicit. See `.howto/record-and-transcribe-audio.md`.

### Independent refused choices

`usePersistedConflict` owns discovery, exact choice binding, the active snapshot and the next document index. A new refused attempt gets a separate scoped key. An explicit edit supplies the exact held record, writes its replacement first and only then compares/removes the old source. Physical copies own distinct JSON snapshots even when the caller reuses one input object. Never rebind an already shown snapshot to another key. Its `capture` reads the authoritative snapshot synchronously; outline adapters do not mirror it in another ref. A canonical capture can retire its exact earlier choice while another choice remains current; later changed words survive.

The common index includes refused-write transients as well as disk records. A consumer must use `nextDocument`, not reconstruct a disk-only list. Readable choices take precedence; malformed originals remain inspectable after them. A passive wake never overwrites currently shown work. If a shown key disappears for an unknown reason, its words remain a separate in-memory choice without recreating the disk key; this current-window retention is not a reload guarantee after external erasure. Quota transients likewise remain explicitly unpersisted under the existing storage warning.

Prayers, outline and templates validate recovery through canonical resource field schemas in `refusedDraftPayloads`, never apply malformed fields, and expose original bytes plus authored strings through the shared `UnreadableDraftCopies` view. Note recovery uses that same read-only view. The legacy-compatible template rename callback remembers the exact selected choice at submission: a late callback cannot replace a newer choice. The current `usePlanTemplates.updateTemplate` returns an ordinary local-capture `Promise<void>` from `documentActions.commit`; remote delivery conflicts remain in canonical engine recovery and `EngineConflictBanner`. A `queuedWrite`/`WriteSubmission` mock exercises a different callback contract and must not be described as proof of that current server path. Keep typed text/answer/outline/template namespaces and owner/document guards separate. Tests include the same-key/equal-object, immediate outline capture, later input, late-template choice, malformed input and quota-only-next-choice paths. Final browser/full-build acceptance remains required.

### Independent copies of a plan cell

`usePlanTextDraft` gives each owner/document opening one stable writer and each cell its own aggregate. `readDraftAddress` discovers both v1 and v2 copies without inferring author chronology from cleanup time. Recovery retains the physical key in addition to node ID; `PlanDraftRecoveryBar` selects a key even when two copies have equal words. Both generated and manual plans pass the same feature contract. `recoveredCells` receives each screen's actual working cell map for the value labelled current; `readPlanText(sermon)` is only the fallback for a missing working field. A deliberate empty string remains empty. Tests that require a particular retained variant explicitly select its physical key; list order or savedAt never proves that the person chose it. Orphans keep every physical version, including one with the same node ID or words; `OrphanedPlanText` passes exact shown cells to `forget`, while current unsaved editor cells remain a separate source.

A clean screen is not proof of durable handoff or server acceptance. Both plan routes pass public `document.state`; `planDraftCheckpoint.ts` permits retirement only with `durable=true`, matching sermon resource/owner and the exact string in checkpoint `planText`. The controller sets durable false when edited and true only after the persisted generation matches. `persist()` can return early during another capture, so resolving an update promise alone is insufficient. A restored source must first appear among this opening's actual dirty/pending words. Compare the entire original source envelope immediately before removal, then strictly verify the key is absent before retiring adopted ownership; unknown, changed or other-document copies remain. `DurableDraftCopy.sourceRecord` keeps the original parsed record independent of projected fields such as note `docId` or `created`; those display fields must never enter a stored-record comparison. Equal words do not prove the source envelope is unchanged. Read-only copies do not persist or retire. This is local checkpoint proof, not a server ACK. Tests: `usePlanTextDraft.test.ts`, `PlanDraftRecoveryBar.test.tsx`, `OrphanedPlanText.test.tsx`. Final browser/whole-class acceptance remains required.

### Invalid note metadata stays readable

`newNoteDrafts.ts` validates reference/tag/source-link metadata through the existing `validateResourceDocument` field schema before an editor or typed preview consumes it. Validate only fields present in the partial backup; do not invent a complete document or apply server text-size limits to authored backup words. A failed payload stays byte-for-byte in localStorage. `UnreadableNoteDrafts` displays only string title/content plus the original JSON, offers text/original copy actions, and never restores, rewrites or discards that source. Mount it outside editor loading/missing branches and in the Studies list so invalid precreate words remain discoverable. Fence both owner and logical document; `exportLegacyRecovery` returns the retained raw bytes. Tests: the malformed-copy matrix in note page tests and `UnreadableNoteDrafts.test.tsx`. This implementation still requires final current-build browser acceptance.

## Retain the last device copy after a form retires

`data-engine/localWriteback.ts` owns only retired local-write handoffs. Live forms keep their existing serializer. `ManualScope.retire`, `MembershipScope.retire` and the closing controller handoff first await the old queue, then repair its final local copy under the original owner/kind/id. `browser.client.ts` shares this pure holder across provider replacement; reads, transport, auth and command authority retain their ordinary lifetime.

- Already-authorized local update/Cancel may finish after UI retirement. Save/proposal producers still require the original current owner. Ordinary same-owner parent-close lets an already-invoked manual Save finish; retirement itself never manufactures Save.
- Reopen/discovery repairs matching pending handoffs before reading the same identity, so a late old write cannot overwrite new typing. `engine.retry` repairs local debt even offline. Preserve the original failure address on every retry.
- Keep membership CAS and its actual returned revision. A local completion can update revision/durability without publishing to a retired UI. Completed or queued Cancel remains cancelled.
- Do not put every live write into another global tail: a queued Save may otherwise wait behind a later update that already waits on that Save. An empty handoff set returns synchronously; adding an unconditional empty await changed background ordering and broke `collectionReturn` regressions.
- Verify with a native IndexedDB transaction held while earlier and latest words are typed, actual signout, and explicit recovery. Separately abort actual device transactions, replace the provider, restore storage and retry the original owner. Tests and RAM retention do not prove survival of browser termination while every device write is refused.

## Why

- 2026-03-16: optimistic records were persisted but retries lived in component refs; a reload, redirect or auth bounce stranded local edits for good.
- 2026-06-14: after moving to Firestore's native offline queue, handlers still awaited `updateDoc`-backed promises and controls hung in "saving" until reconnect.
- 2026-06-14: ids and timestamps minted inside the mutation function duplicated children and rewrote history with replay time on resume.
- 2026-10-03: a tracker entry said moving between notes keeps the editor mounted and loses the last 250 ms; live it remounts. The real hole of that class is an account change under the offline shell, left open: three hook patches in a row each lost someone's text.

See also: `.howto/write-a-document-field.md` · `.howto/read-while-offline.md` · `.howto/update-react-query-cache.md`

Feature recovery uses the public `data-engine/react.client` facade: `discoverLegacyRecovery`, owner-fenced exact-byte `exportLegacyRecovery`, and `isValidRecoveryPatch` for canonical partial-field validation. Never import storage/schema internals from a screen or feature utility and never add a boundary exception. A failed precreate refresh may retire its earlier owned value only if the entire stored envelope still matches the captured source; matching words or creation ID alone are not that proof.

For a last-keystroke departure proof, waiting for the first backup and then logging out proves only retirement of an already-kept copy. Add real keyboard input immediately before the actual logout click, record both trusted DOM events with the same monotonic clock, assert the required interval and verify the added tail after reopening/reload. Make that timing assertion part of the aggregate verifier; an ordinary-path receipt without it must fail that requirement. An explicit independent backup fixture proves preservation of that source, not a second user's activity or an action order across devices. Keep a mounted owner-change isolation control separate from the real one-owner logout/reopen path. Unit191 records77.1ms/130.7ms final-input controls and the former receipt's negative check.
