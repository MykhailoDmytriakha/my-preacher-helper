# Migrate a domain to the data engine

The canonical implementation is now `frontend/app/data-engine/` in `main`. Move a domain through the public `react.client.tsx` facade, one collection at a time; fix shared merge, offline or conflict behavior in the engine with a shared regression. Preserve older clients' device input before it can be overwritten. Read `frontend/app/data-engine/README.md` and `docs/architecture/data-engine-migration-log.md` for current activation and remaining work; historical checkpoints in the log are not current rollout status.

## How

- Screens read and edit through `useDataDocument` / `useDataForm` / `useDataCollection` (`.howto/use-data-engine-in-a-screen.md`). A domain hook that keeps its screens unchanged exposes the legacy hook's interface and picks the road with `isCollectionOnEngine`, calling both hooks with complementary `enabled` flags (`frontend/app/hooks/useServiceOrders.ts`).
- The engine was merged into `main` on 2026-09-25; the log records ten activated production collections. Verify live switches before claiming present activation. `users` consumers were migrated locally on 2026-09-28; verify production activation separately. Server-only study-material routes remain an explicit exception, and collection-wide legacy closure remains pending.
- The collection is registered once: its writable fields in `getResourcePolicy` (`frontend/app/data-engine/protocol.ts`) and its shape in `frontend/app/data-engine/resourceSchemas.ts`.
- Legacy writers of an engine collection refuse with the typed `data-engine-required` (`assertLegacyClientWriteAllowed`), so an unmigrated screen fails visibly instead of writing around the engine. Server-computed writes go through `writeOwnedDocument` (`frontend/app/data-engine/serverEdit.server.ts`).
- The bypass ledger `frontend/__tests__/architecture/legacyFirestoreAccess.json` (checked by `dataEngineBoundary.test.ts`) only shrinks — never add an exception.
- Previous clients' input: `DataEngineMigrationGate` mounts before `QueryProvider` hydrates, because even restoring the persisted cache can expire or delete the last copy. It starts archiving owner-scoped cached rows and paused/error mutation payloads first. If storage is silent, the app proceeds after the bounded wait while query-cache persistence stays disabled until archival finishes; an archive failure is shown with Retry. Only collections listed in the gate and in `QUERY_SOURCES` (`frontend/app/data-engine/legacyQueryRecovery.client.ts`) are archived. Once switched, legacy query rows of that collection are session-only (`shouldPersistLegacyQuery`).
- Archived copies are evidence for the person, not a baseline. `LegacyDataRecoveryNotice` lays them out; `retireLegacyEchoes` removes only copies proven equal to the server copy; the rest wait for an explicit decision or export. A cached final value never becomes an automatic server update and never gets an invented opening ancestor.
- Do not replay old transforms after migration. The legacy series outbox (v2) lost action grouping and opening ancestors, so enabled clients stop legacy replay and offer exact owner-scoped export through `frontend/app/data-engine/legacyRecovery.client.ts`; BUG-20260919-series-legacy-replay-splits-move stays open on the inactive legacy path. The same rule holds outside the engine: when old local persistence is folded into a new store, keep a read path for the old persisted records — dropping unsynced data breaks the offline contract.
- Order: protective rules deployed before the first engine write, then the collection switches, then every device reloads, and collection-wide closure (`DATA_ENGINE_CLOSED_COLLECTIONS`) last, as its own step. After the first engine write, switching the client off is not a rollback.
- Mixed phase (`legacyOpen`): old writers publish no feed event, so an unchanged engine head cannot certify their data. `CollectionReader` (`frontend/app/data-engine/collections.ts`) owns a five-minute sweep per watched collection, also sweeping on opening, tab return and reconnect; it suspends hidden/offline and backs off after failures. Closed collections use the feed alone. Keep the mixed phase short.
- `docs/architecture/data-engine-operations.md` records measured protocol operations, not a proven daily production billing budget. Never expire acknowledgement receipts without a protocol that rejects retired operation identities.

## Legacy paths (unconverted collections only)

These compatibility mechanisms are not templates for new features: `conflictSafeUpdate`, `revisionedUpdate`, `recoverableWrite`, `useDocumentFreshness` and its projections, `seriesMembership.client.ts`, `ownerListRead.client.ts`, and React Query paused mutations. They remain relevant only while their collections have not migrated. Keep the architecture exception ledger shrinking.

## Why

- 2026-09-23: the mixed-mode sweep ran every 15 s; QA tabs left open exhausted the project's daily read allowance. It is now five minutes.
- 2026-09-25: the first release archived the whole previous cache (115 copies in one browser, all echoes); rows are still archived because a council's refused or unsent text lived only in its cached row, and echoes are retired by comparison.
- 2026-09-19: replaying the legacy series outbox split a move — the addition to a deleted target was refused while the source removal succeeded.
