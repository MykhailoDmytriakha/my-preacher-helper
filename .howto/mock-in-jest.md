# Mock a module in a Jest test

Global mocks live in `frontend/jest.setup.js`: `next/router`, `next/navigation`, `react-i18next`, `i18next`, Firebase app/auth/firestore, `@/services/firebaseAuth.service`, `@/hooks/useAiUsage`, the react-markdown chain, `next/image`, `jspdf`, `music-metadata`. A test file adds or overrides with `jest.mock(path, factory)`: write every factory explicitly, mirror the real export shape, and spread `...jest.requireActual(path)` when you replace only part of a module.

## How

- Mirror the export shape: a named export is mocked as `{ Name: … }`, a default one as `{ __esModule: true, default: … }`. A mismatch hands React `undefined` → "Element type is invalid … got: undefined". Example: `RichMarkdownEditor` is named (`frontend/__tests__/components/CreateThoughtModal.test.tsx`).
- Partial mock → spread `...jest.requireActual(path)` first, then override (`frontend/app/utils/__tests__/studyNoteUtils.test.ts`). A factory without it drops every export it does not list, and the next export added to the module fails as "X is not a function" in a test that never mentioned it. Write a full explicit object only when loading the real module is itself what breaks (Firebase init, ESM-only code).
- Hoisting here is SWC, not Babel: `next/jest` puts Next's SWC transformer first in `transform`, so the babel-jest entry in `frontend/jest.config.ts` never runs. SWC lifts `jest.mock` above the imports without checking names, so Babel's "not allowed to reference out-of-scope variables" never appears. The failure comes at run time: `ReferenceError: Cannot access 'x' before initialization`, when the factory runs during the imports, before the file's `const` lines. So: string-literal path; give outer spies a `mock` prefix and read them lazily inside a function (`useAiUsage: () => mockUseAiUsage()`); build React inside (`const React = require('react')`); or load the subject after the mocks — `await import(...)` in the test (`frontend/__tests__/api/clients/structuredOutput.test.ts`) or the unhoisted `jest.doMock`.
- Inside a factory `require('react')` is untyped: `React.useState<T>()` fails `tsc --noEmit` with TS2347 "Untyped function calls may not accept type arguments" (tests are type-checked — `frontend/tsconfig.json` includes `**/*.tsx`). Drop the type argument there. In a `renderHook` harness with a real React import, annotate broad shapes explicitly: `React.useState<Record<string, Item[]>>`.
- A local `jest.mock` of a module the setup already mocks replaces the setup factory whole — list every export the component calls.
- Testing a module the setup mocks: `jest.unmock(path)` at the top of the file, or `jest.resetModules()` + `jest.unmock` + `jest.doMock(dependencies)` + `jest.requireActual(subject)` (`frontend/__tests__/services/firebaseAuth.service.test.ts`). Otherwise you assert against the setup stub.
- Markdown: react-markdown, remark-gfm, rehype-raw and rehype-sanitize are stubbed globally and print markdown verbatim: a normal test proves structure, never appearance. For real output, unmock all four at the top (`frontend/app/components/ui/__tests__/FoldableMarkdown.rendered.test.tsx`). That works only because `frontend/next.config.mjs` lists the ESM chain (`MARKDOWN_TEST_PACKAGES`) in the test-only `transpilePackages`. The `transformIgnorePatterns` in `frontend/jest.config.ts` has no effect: `next/jest` puts a blanket node_modules rule ahead of it.
- Navigation: the setup's `useSearchParams` is a `jest.fn` returning `{ get, toString }`; its `useRouter` returns fresh spies on every call, so `push` cannot be asserted through it. Mock `next/navigation` locally with stable `mockPush` / `mockReplace` and `useSearchParams: () => mockUseSearchParams()` (`frontend/__tests__/pages/dashboard.test.tsx`), or `(useSearchParams as jest.Mock).mockReturnValue(new URLSearchParams('planView=overlay'))`.
- nuqs: mock `useQueryState` with an internal `React.useState`, so setting it re-renders like the real hook; a static value never changes (`frontend/__tests__/pages/prayers.test.tsx`).
- i18n: the global `t` returns a few fixed strings or the key; it ignores `defaultValue` and parameters. A local `t` returns the key and interpolates the parameters the test asserts on (`Toggle ${options?.title}` in the FoldableMarkdown test).
- React Query hooks need a `QueryClientProvider`, or "No QueryClient set". Use `TestProviders` / `createQueryWrapper()` from `frontend/test-utils/test-providers.tsx`.
- Headless UI v2 renders in JSDOM here (`frontend/__tests__/components/navigation/MobileMenu.test.tsx` uses the real library). If you mock `@headlessui/react` to drop transitions, export every named piece the component imports: `Dialog`, `DialogPanel`, `DialogBackdrop`, `DialogTitle`, `Transition`, `TransitionChild`, `Popover*`, `Listbox*` (`frontend/__tests__/components/Column.deleteModal.test.tsx`).
- Rich editor: mock `RichMarkdownEditor` as a `<textarea>` wired to `value`/`onChange` — TipTap's contenteditable does not work in JSDOM. Only the editor's own test mocks `@tiptap/react` instead (`frontend/__tests__/components/ui/RichMarkdownEditor.test.tsx`).
- Icons: a test that mocks `@heroicons/react/24/outline` with an explicit list crashes ("Element type is invalid") once the component uses an icon not in it. Add the new icon to every such mock (`frontend/__tests__/components/ThoughtCard.test.tsx` and eight more).
- date-fns: Jest rewrites `import { format } from 'date-fns'` to `date-fns/format` and `import { ru } from 'date-fns/locale'` to `date-fns/locale/ru` (`modularizeImports` in `frontend/jest.config.ts`, the same split the production build does). Mock the deep module the code ends up importing, one `jest.mock` per function: `jest.mock('date-fns/format', () => ({ format: … }))` (`frontend/__tests__/components/calendar/AnalyticsSection.test.tsx`). A `jest.mock('date-fns', …)` now replaces a module nobody loads: the real function runs, and only a test that reads the mock notices. `Cannot find module 'date-fns/<name>'` in Jest while the app works: either a new date-fns export without a module of its own (add it to the first `date-fns` pattern in `MODULARIZED_IMPORTS`), or a form the rewrite cannot handle — `import('date-fns')` and `export * from 'date-fns'` become `require("date-fns/")`; use a static named import.
- Do not mock visual-only components such as skeletons: let them render and find them by `data-testid` (`dashboard-stats-skeleton`).
- Firebase Admin: `FieldValue` comes from `frontend/app/config/firebaseAdminConfig.ts`. A mock of that module without `FieldValue: { serverTimestamp: () => 'mocked-server-timestamp' }` throws "serverTimestamp is not a function" in telemetry and routes (`frontend/__tests__/api/admin/telemetry/promptNameRoute.test.ts`).
- Route handlers: mock `next/server` so `NextResponse.json` returns `{ status, headers, json }` (`frontend/__tests__/api/admin/adminMeRoute.test.ts`).
- Env: set `process.env` in `beforeEach`, delete or restore it in `afterEach`. The setup deletes the deploy switches (data-engine, Google client id, test login, the old `NEXT_PUBLIC_USE_CLIENT_*`), so a test opts in itself (`frontend/__tests__/architecture/buildEnvIsolation.test.ts` guards the data-engine ones). A value read at call time (`isCollectionOnEngine`) only needs the env set. A value captured at import (`const API_BASE = process.env.NEXT_PUBLIC_API_BASE` in `frontend/app/services/brainstorm.service.ts`) needs `jest.resetModules()`, then the mocks, then the import.

## Sequences and leftovers

- `clearMocks: true` and the setup's `jest.clearAllMocks()` clear calls only. A `mockReturnValue` set in one test and an unused `mockReturnValueOnce` both carry into the next test in the file. Reset what you configure (`.mockReset()` in `beforeEach`). To override a `beforeEach` default for a whole test, use `mockReturnValue`, not `…Once`, or reset first.
- Chains of calls (AI steps): queue `mockResolvedValueOnce` in call order and assert with `toHaveBeenNthCalledWith`. Parallel requests take the queued values in start order: queue one per request of a batch before the next sequential step.
- Several adapters with the same client shape: give each constructed client its own spy (the `openai` mock in `structuredOutput.test.ts` returns `openaiParseMock`, `geminiParseMock` or `openRouterParseMock` by `baseURL`). Assert the chosen call and `not.toHaveBeenCalled()` on the others; a shared spy lets a hard-coded adapter pass.

## Why

- 2026-09-29: the whole `date-fns/locale` barrel (every locale in the package) was loaded by each test file that formats a date; rewriting the imports for Jest cut 194 date-related test files from 101.7 s to 91.4 s on one worker, and four barrel mocks moved to deep paths.
- 2026-09-16: a partial mock of the scripture helpers broke when the module gained `scriptureReferenceSearchText` — hence `...jest.requireActual` on every partial mock.
- 2026-07-12: a shared spy across provider adapters let hard-coded adapter selection pass.
