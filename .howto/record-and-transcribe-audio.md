# Record and transcribe audio

The browser records with `MediaRecorder` and posts the blob to a transcribe route: `/api/thoughts/transcribe` and `/api/studies/transcribe` through `transcribeAudioWithRetry` (`frontend/app/utils/transcriptionRetryClient.ts`), a new dictated thought to `/api/thoughts` through `createAudioThought` (`frontend/app/services/thought.service.ts`). The server makes one transcription attempt and answers a failure with a typed contract; retries belong to the client, and raw audio remains in the canonical owner-scoped recording store until its text is durably accepted or the person explicitly discards it.

## How

- Retry where a fresh time budget exists: the server calls `createTranscriptionWithRetry` with one attempt by default (`frontend/app/api/clients/transcriptionRetry.ts`) and maps failures with `mapTranscriptionError`. Transient kinds (`network` incl. `ECONNRESET`, `rate_limit`, `server`) → `503` + `retryable: true` + `phase: 'transcribe_audio'` + `kind`. The client retries as new HTTP requests, each with its own 60 s budget. `transcribeAudioWithRetry` (2 retries by default) retries when the body says `retryable`, or by HTTP status when a 5xx/429 came with no body (a function killed at the wall); `createAudioThought` retries only on `retryable` + `phase === 'transcribe_audio'`.
- Non-retryable kinds stop at once: `billing` (`insufficient_quota`, 429), `auth` (401), `invalid_audio`, `bad_request`. `classifyTranscriptionError` checks the most specific signal first — billing before a generic 429.
- Every attempt's error is kept in `TranscriptionClientError.attempts`; a 200 with empty text counts as `invalid_audio` (silence), not success.
- Inside one attempt the model chain is the tier's allowed transcription models, each with a share of the 45 s budget and SDK `maxRetries: 0` (`createTranscription` in `frontend/app/api/clients/openAI.client.ts`).
- Keep the blob at the recorder: after a valid recording fails, the recorder that owns it keeps it listenable with retry / discard / record again (`frontend/app/components/audio-recorder/useAudioRecorderLifecycle.ts`). The parent hands back an error scoped to that recorder through `transcriptionError` / `onRetry` / `onClearError` on `AudioRecorder`; one page-wide error state shows failures in the wrong recorder or closes the popover before recovery.
- Surviving navigation/reload: park every completed nonempty blob in the canonical `recordingDraftStore` IndexedDB store BEFORE provider work. Scope by authenticated owner, context and original destination; there is no age-based deletion. Missing/unavailable storage is a failed park, so retain the in-session source and do not start recognition. `useRecordingDrafts`/`RecordingDraftBanner` use the same store, refresh on store/focus changes and fence obsolete list/actions when owner or destination changes.
- Acceptance is separate from recognition: `useTextDictation` caches transcript with raw source, publishes a stable source ID and retains raw until the matching text is accepted by the existing durable writer. Capture source IDs at submission, not at completion; an older save must not release a later take. Cached retry never appends an already represented source twice. Discard awaits the owner's durable tombstone; a late park/transcript cannot revive it. Shared `useRecordingDiscard` prevents an old delete completion clearing a newer take.
- Study creation changes destination from `new` to the created note ID. Persist `recordingSourceIds` for every parked raw source, including failed/empty recognition, separately from `dictationSourceIds` for represented text. Carry only this editor's source IDs; metadata links retain access if moving raw fails. `recordingDraftScope` permits `study/new` fallback only for exact linked IDs. The creation handoff must wait for active capture, pending raw parking and unpreserved audio; existing-note saves keep working. `studyNoteRecordings` centralizes optional metadata for drafts/engine writes.
- Consumer acceptance: local Thought/Prayer forms wait for their captured save persistence; Engine Thought and Scratch await the canonical document update. Sermon/outline recorded-thought creation sends a stable recording ID; the authenticated route checks owner/writability first, then reuses an accepted `audio:<id>` thought before calling the provider again. This is accepted-result idempotency, not provider single-flight for simultaneous requests. Outline recovery retains original section/point/subpoint and refuses a missing/locked target instead of redirecting its words.
- Legacy ownerless raw may be adopted only after a loaded study/sermon proves the signed-in owner; unknown rows are left untouched. Audio remains device-local and is not copied to another device by this mechanism. Browser storage eviction remains outside this retention contract.
- Microphone ownership: both FocusRecorderButton and useAudioRecorderLifecycle use useRecordingSession. One attempt stays active from requesting permission until final data has been handed off, including paused capture and asynchronous stop finalization. onRecordingStateChange communicates that interval to modal hosts. Late grants from an unmounted/cancelled attempt stop their own tracks; late failures never call a retired owner. A pending permission request must have an enabled recorder Cancel so the editor is not trapped.
- Replacement and retry: retain the previous playable blob and parent retry source until MediaRecorder.start succeeds. Permission, constructor or start failure keeps them. Cancelling pending acquisition does not discard the old source. Retry must not call onClearError before consuming the saved blob: real consumers use that callback to delete the retry source. Explicit discard/cancel and successful replacement retain their existing cleanup.
- One container per recording: call `MediaRecorder.start()` with no timeslice. Audit every surface — `useAudioRecorderLifecycle.ts` (through `createConfiguredMediaRecorder`) and `frontend/app/components/FocusRecorderButton.tsx`, which builds its own recorder. One leftover `start(100)` brings back malformed WebM; `frontend/__tests__/components/FocusRecorderButton.test.tsx` asserts `start()` with no arguments.
- Timing has one source, `frontend/app/utils/audioRecorderConfig.ts`: base length (90 s, `NEXT_PUBLIC_AUDIO_RECORDING_DURATION`) and the 5 s end countdown (`GRACE_PERIOD_SECONDS`, `NEXT_PUBLIC_AUDIO_GRACE_PERIOD`). Recorders and the server's `validateAudioDuration` (total + 2 s) read the same config — never hard-code a timer.
- Auth and metering: `.howto/gate-and-meter-an-ai-call.md`.
