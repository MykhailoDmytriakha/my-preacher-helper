# Run a live check that changes data

An agent's live data check drives the real app on a dedicated local server connected to isolated Firestore and Auth emulators. Follow [Run a demo on the emulator](run-a-demo-on-the-emulator.md) for setup, canonical seed commands and owned-hub export. Confirm the actual browser SDK emulator port and Admin SDK host before opening data views; keep `NEXT_PUBLIC_API_BASE` empty. A production-built stand must compile the public emulator settings before `next start`. Use an owned synthetic test identity and deny production database traffic. Select the linked recipe's separate Auth-emulator procedure beginning “For an admin-only outage stand”; its introductory real-sign-in setup alone does not supply the Auth isolation required here. Require `FIREBASE_AUTH_EMULATOR_HOST` on the scoped server and actual local Auth SDK/lookup evidence. If the serialized browser session asks `accounts:lookup` at the compiled cloud origin, forward only that exact, owner/audience-checked request to the owned Auth emulator and use its real response, as that procedure describes; deny cloud Auth delivery. The ordinary manual server can use production credentials, so localhost alone does not establish isolation. The owner left the general launch-default choice open; this recipe changes no shared launcher or manual-server configuration.

## How

- **Output to a file, never through `| head` / `| tail`.** A closed pipe kills node with EPIPE in the middle of the run — after a change, before its undo (2026-10-29: a link stayed in the test user's analysis). `node live-x.cjs shots > out.txt 2>&1; cat out.txt`.
- **The script cleans up its exact own fixture in the same run and records completion.** Guard cleanup by owner, original generation and expected content; verify the canonical result. If create delivery is unknown, establish that the record belongs to the original operation before deleting or replaying anything. A missing completion marker means the run stopped early: inspect its retained diagnostics and exact fixture.
- **Wait for acknowledged saving before closing the browser.** Require the actual command acknowledgement and canonical readback of the intended result; elapsed time alone does not prove persistence. Closing right after «Отменить» lost the undo (2026-10-29).
- **A visible zero is not a delete ACK.** On 2026-10-31 the paragraph check closed after1.5s and left three unsent deletes. Apply the same exact ACK and canonical readback rule to deletion; clean up in finally before closing.
- **A fresh browser starts in English**: add the cookie `lang=ru` before the first page (`reference_fresh_probe_starts_english`), and pick places by their buttons, not by text that depends on the Bible's language.
- **Select by role and name, as a person sees it** (`getByRole('button', { name: 'Готово', exact: true })`); a test id only where nothing visible names the thing. A screen redesigned the same day breaks a script that clicked an old row — update the script, not the screen (the analysis badge's window lost its row «Разбор · место» on 30.10; scripts open the analysis by «Открыть разбор …»).
- **Wait for the controls being measured, separately from the text.** A visible verse does not prove that the responsive header or marks toolbar has mounted: `useMediaQuery` resolves in an effect and `useReaderMarks` waits for marking support, identity and local-store readiness. Record the first presence/rectangles, wait with a bounded DOM predicate for the same required controls, then apply the unchanged size/position assertions. Never inject controls or change the app to satisfy a premature observation. On 30.10 the first tablet query saw no toolbar; it appeared469ms later and the same13 assertions passed. Keep each incomplete run and its frame under its own artifact name; never overwrite failure evidence or report a stopped batch as wholly successful. A successful aggregate across attempts must name which completed cases it uses.
- **Measure real tab return with ordinary browser focus.** Launch a disposable installed Chrome profile and connect to its default context with `noDefaults: true`. In a return test, require the destination to lose focus while the other tab is active, then receive a trusted focus event on return. A static `document.hasFocus()` result can come from Playwright focus emulation. Keep reports without the required transition apart from application behavior. The Scratch check in Unit330 compares both modes on the same build.
- **A browser-evaluated function cannot read a Node closure.** Pass its inputs explicitly or read the element's own attributes; `locator.evaluate` serializes its function. Syntax checks alone did not catch a Node `start` referenced inside the browser. Keep unreached targets `null` and `qaComplete: false`, preserve the exception/frame, and do not count default false fields as observed product failures. Completed false targets make the regression red; QA completion and a passing product result are separate verdicts.
- **Read the actual accessible role before freezing a callback.** A visible button-shaped switch can expose `role="switch"`; query that role and verify `aria-checked`. For a rounded SVG path, its quadratic control points describe the orthogonal routing polygon, not the painted curve. State which clearance is measured and preserve the raw path/samples and image; do not turn a polygon threshold into a universal painted-distance claim. A synthetic8px glyph test does not prove the live glyph measured8px.
- **Copy exact identifiers from the producing tool.** Bind Git parents, build IDs, subprocess exits and test totals to actual receipts; do not hand-type or infer an omitted envelope field. Preserve a mistaken receipt and its explicit correction.
- **Check the whole receipt handoff when adapting a stand.** A prepared-input verifier does not exercise READY or stop. Every provenance field read by shutdown must also be copied into READY from the verified inputs. Compare the actual producer and consumer schemas before launch; a missing field is a harness failure, not proof that baseline data changed. Exercise the adapted validator against a retained completed sample before starting services; syntax-only checks do not resolve missing runtime imports or free variables. Preserve that failed run and retry in a fresh namespace without rewriting its receipts.
- **Hit wrapped inline text by its fragments.** Its union rectangle can cover blank space between lines; use real client/range rectangles and require `elementFromPoint` to hit the intended element or a descendant before a trusted mouse click. Natural Tab may reveal only the button at the viewport edge: scroll the whole verse into view before measuring its text clearance. Preserve the failed attempt and repeat the unchanged product oracle in a fresh namespace.
- **Distinguish server-owned fixture fields from authored content.** Canonical group writes may add `rev` as well as timestamps. Preserve the full acknowledged snapshot for strict unchanged/cleanup checks; compare authored input only after excluding fields the actual protocol owns. Save the attempted input and ACK before asserting, so a failed comparison still identifies its exact temporary record.
- **Scope browser storage setup to the application origin.** A context init script also runs on `about:blank`, where localStorage access can fail. Check `location.origin` before restoring the isolated Auth session; retain an already failed attempt instead of rewriting its diagnostics.
- **Hold the exact document read when measuring a cold page.** A collection prefetch can begin before the client document screen mounts. Wait for the selected document's actual request and visible Back control before measuring its pending state. Leave responses unchanged; collection arrival alone is not proof the intended page is under observation.
- **`page.route` does not see a GET the app's service worker answers.** The worker fetches `/api/*` GETs itself, so a stubbed `/api/health` never reaches the page and the screen hears the real server: 2026-11-07 the outdated-tab notice stayed silent and looked broken, while the stub was simply bypassed (POSTs were intercepted, so the refusal itself appeared). Create the context with `serviceWorkers: 'block'` when a check stubs a GET; Serwist then logs `reading 'waiting'` page errors — the stand's, not the app's (`.cases/2026-11-07-feedback-structure-edit-refused/stand/live-outdated.cjs`).
- **A check without a network runs with the app's worker, and keeps the Bible's files off the device itself.** `context.setOffline(true)` cuts the network for the page and for the worker. `page.route` does not see what the worker fetches; with `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` set before `require('playwright')`, `context.route` does (Chromium), so a book's file can be aborted until the network "returns". The reader's background warm-up starts when the page is idle (or 2 s after it opens), three books at a time; on a local server it had all 66 books within seconds of opening `/bible` (2026-11-12). Abort `**/bible-text/**` from the first page and empty the `bible-text` cache (`caches.delete`) before each scenario, or the books are already on the device and nothing is missing. With the worker blocked the reader waits on «Готовим книгу…» (press «Читать сейчас»). Record every `/api/health` answer (the knock: the moment the app's answer turns to yes) and the requests of each file before and after the return (`.cases/2026-09-29-live-fix-stream/artifacts/live-reconnect.cjs`, 2026-11-12).
- **Count, then look**: print the numbers that prove the outcome (flags, lines, arrows, the address) and take a screenshot to look at — a count says it happened, the picture says it looks right.
- **The reader's Bible is the device's, not the address's**: `tr=` in a reader address counts only with `analysis=`; without it the reader opens the Bible kept in `localStorage['bible:translation']`. A check «in the King James» sets it before the first page (`context.addInitScript`) — 2026-11-05 a KJV check read the Synodal and proved nothing (`live-p14-kjv.cjs`).
- **In WebKit (Safari's engine) wait ~8 s after the sign-in click before the first `goto`**: sooner, the sign-in's own move to `/dashboard` cuts it («interrupted by another navigation to /dashboard»); the app moves once, there is no loop (probe 2026-11-05). Desktop WebKit with touch keeps `navigator.maxTouchPoints` at 0 — fake 5 for an iPad (`tools/webkit-lab/gestures.js`). Playwright's `tap()` in WebKit gives real `pointerType: 'touch'` events; a hold has no API — send WebKit's own `PointerEvent` of type `touch`, down, 900 ms, up (a verse's menu opens on the lift). A Pencil is the same with type `pen`; such a pointer is not live, so `setPointerCapture` on it throws «NotFoundError: The object can not be found here» — the probe's, not the app's (`live-p14-webkit.cjs`).
- **Close what you started**: the browser at the end of the script; the dev server at the end of the work unless the owner is trying the change on it (`fix-stuck-dev-server.md`).
