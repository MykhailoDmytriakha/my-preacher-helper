# Save several documents atomically

For engine-owned series, stage a multi-document action through `useDataMembership()` in `frontend/app/data-engine/react.client.tsx`; one Save captures one command for all participants. A new member created inside a series uses the same stage. Fields of one sermon that must agree use one `useDataForm` command. See "Series membership actions" in `frontend/app/data-engine/README.md` and `docs/architecture/data-engine-atomic-edits.md`.

## How

- Call `begin()` before opening the selector, confirmation or drag: it pins the displayed series copies and their exact saved predecessors. `update(action)` stages durably without sending; `save()` freezes the stage and captures one command through `CommitQueue.saveAtomic` (`frontend/app/data-engine/commits.ts`). Never read a fresh baseline at Save, never open a new stage inside an old form's Save callback.
- Participant ownership, proofs and cancellation live in `frontend/app/data-engine/atomicCommits.ts`: one queue, one journal, no second transport.
- Delivery belongs to the whole action: `delivery`, `retry()` (same identity), `discard()` only for proven failed delivery (`delivery.canDiscard`). Discard retires the whole chain and restores membership while keeping later metadata edits and conflicts. Unknown delivery is retried, never replaced. A participant document's Keep local / Accept remote cannot resolve an atomic action. UI: `DataMembershipStatus`; `SeriesMembershipRecovery` mounted once in the private workspace; selectors reuse `SeriesMembershipDialog`.
- New member inside a series: `beginCreate(collection, initialValue, requestedSeriesId?)` durably owns the new ID and typing before any catalog read; `updateCreation` persists typing; only `openSeries()` reads and pins the destination catalog; `update(null)` means standalone. One `save()` validates the whole draft and captures `series-member-create`. A preset series blocks Save until it is pinned and selected or explicitly cleared, and survives restart. Retry keeps the ID and capture identity. Consumers: `EngineCreateSermonModal`, `AddSermonModal`, workspace recovery; `useSermonsDataCollection` shows submitted creation in lists and the calendar.
- Storage: creation stages and requests use their own ranges (`creation-scope`, `creation-request`) so older readers cannot recover half the intent; reference rows keep predecessors alive. A capture reference is written in the same IndexedDB transaction that creates the request (`frontend/app/data-engine/commits.client.ts`) and moved to the stage when it completes (`frontend/app/data-engine/membershipScopes.client.ts`).
- Thoughts: Save-button editing is `EngineThoughtModal` + `useDataForm`, never a late patch against a newer ancestor. The pure transforms in `frontend/app/utils/sermonThoughtEdits.ts` (`addSermonThought`, `patchSermonThought`, `replaceSermonOutline`) change the thought, `structure` / `thoughtsBySection` and outline together; outline writers update affected assignments in the same command.
- Server side, `applyCommand` (`frontend/app/data-engine/protocol.ts`) runs `preservesSermonLinks` on the merged candidate: new dangling point / sub-point references, placements of missing thoughts and duplicate placements are refused; defects already present and untouched stay repairable.

## One-shot council carry

The carry facade resolves after durable local capture, not server acceptance. `components/council/councilActionNotice.ts` presents a neutral prepared-carry sentence and the destination link; shared DataMembershipStatus/DataSyncStatus owns delivery/refusal. Both finish screens use its neutral Undo capability notice for eight seconds, including offline. Never turn local capture into a success toast or delay Undo until the network answers. For the single-document Finish/Undo lifetime, see `.howto/keep-a-write-across-offline.md`: the domain hook captures before navigation and returns an entity-bound reversal through the existing action facade.

An unfinished council topic uses useDataDocument().carryCouncilTopicToNew(topicId, title) when no destination exists, or carryCouncilTopicToExisting(topicId, destinationId) for a preparing council. The facade freezes the displayed checkpoint before awaits; councilCarry.ts selects the parent's proven pending predecessor and captures only that topic. CommitQueue.saveAtomic owns the source mark and absent destination together. councilCarryContent.ts shares the copy rule and new-destination validation with the server. A new council is preparing and undated. An existing destination pins its cached confirmed copy plus one unambiguous saved chain; it never adopts unsent editor text. Both participants retain their own proven predecessor. Content gets fresh stable child IDs per invocation and no past outcome. Server and client share the single-append/content rule; existing destination topics stay intact.

getActions/discardAction expose whole-action delivery with the existing DataMembershipStatus presentation. Never resolve one participant with a document-level choice. Source cancellation keeps captured/later words and removes only its own marks, measured against the initialized predecessor. Destination cancellation reverses only the appended copy through the normal merge; unrelated later words remain, while edited copied content stays recoverable through conflict. A page closing after invocation does not cancel capture.

Council requests use council-carry-request, hiding unsupported participants from older bundles. After all participants are terminal and BOTH actual ACK snapshots are durable, the engine releases projection references through CommitStore.releaseProjection; checkpoint references keep proofs needed for unsent typing. Unknown delivery retains ownership. Tests: app/data-engine/__tests__/councilCarryAtomic.test.ts.

## Analysis passage reshapes

`utils/studyAnalysisReshape.ts` plans a passage change without writing. A source-only edit uses ordinary `updateNote.capture`; moved authored work uses `useStudyNotesEngine.reshapeNotes` through `useDocumentActions().reshapeStudyAnalysis`. The note adapter reuses ordinary creation defaults and the exact stored reference ancestry behind locale-normalized readings. Feature code does not construct protocol commands or manage request rows.

`data-engine/analysisReshape.ts` pins every existing note through shared `savedDocumentPin.ts`, freezes only the planned frame, and captures source plus up to two recipients through the existing atomic queue. A stale, deleted, foreign, ambiguous or decision-waiting participant refuses the action before source mutation. The `analysis-reshape` relation checks all participant frames before exposing server writes. `analysis`, `content` and `scriptureRefs` stay together; only a touched title joins them, and unrelated metadata retains its owner.

Requests use their own `analysis-reshape-request` range and the existing participant retention, journal, ACK and whole-action cancellation. Predecessor acknowledgement must not reinterpret positional work in a different frame. ACK/cancel preserves a later authored frame whole and exposes a conflict where needed. The compound guard remains stricter than ordinary same-passage merging.

Ordinary positional saves append complete before/after `analysis`, `content` and `scriptureRefs` roots through `prepareDomainCommand`, including unchanged fields. `mergeDocumentFields` and server admission share `keepAnalysisPositionFrame`: different normalized passage bases retain the entire authored frame and expose one three-root conflict. Unknown bases are not equal; title-only legacy edits remain available. Same-basis generic map merging stays in place, including its existing conflict when derived content differs. A persisted older command missing the frame proof receives `decision-required` and remains recoverable; neither current server fields nor delivery time can supply its missing ancestor.

Explicit Keep Local chooses the whole original local passage and its marks, then prepares a new full-proof ordinary update against the current copy. It must not lay old indices onto the newer range. Request-scoped cancellation keeps later unsent cross-basis work undecided through `dropRefused`. Test the ordinary ACK, restart, both explicit choices and compound predecessor/cancel paths separately. Bible text currently uses immutable v1 corpus assets; this fix does not migrate old indices across future corpus revisions.

The reader waits for complete durable local capture, blocks duplicate Apply within its owner/book/Bible scope, and gives neutral prepared feedback. `AnalysisReshapeRecovery`, mounted once in the private workspace, uses `subscribeSavedWork` and the existing action delivery presentation after navigation; it adds no database polling. A single document cannot resolve one participant. `requiresWholeActionResolution` derives that boundary through the canonical cancellation scope for generic recovery, retaining Open/Copy while removing an impossible participant-level choice. A later ordinary request after a completed atomic action remains independently decidable. The `decision-required` refusal uses a translated instruction to decide the earlier change; it does not promise a two-version choice for a whole action.

## Legacy paths (unconverted collections only)

The old `useSeriesMembership` / `seriesMembership.client.ts` writer is compatibility code, not a template for a new multi-document action. Do not chain its calls or independent document saves to imitate atomic Save.

## Why

- 2026-09-19: another editor consumed the ACK before the stage had recorded its request IDs, and compaction erased the evidence that deduplicates the action after a restart. The reference is now acquired with the request and transferred in one transaction.
