# Show an error once

Some typed errors already have one owner that tells the person. The usage cap (`UsageCapReachedError`) is announced by `UsageCapGlobalHandler` (`frontend/app/components/usage/UsageCapGlobalHandler.tsx`, mounted in `frontend/app/providers/QueryProvider.tsx`). Every UI `catch` must recognise such an error first and step aside: no toast, no generic message, no retry draft.

## How

- First line of the catch: `if (isUsageCapReachedError(error)) return;` (after any local cleanup), before generic formatting, `toast.error`, or saving anything for a retry. Examples: `usePlanActions.ts`, `frontend/app/components/column/audio.ts`, `studies/[id]/page.tsx`.
- Keep cleanup (loaders, per-item pending flags) in `finally` or inside the guard branch, so the early return does not leave a spinner running.
- Do not persist a recovery copy for an owned error; it can only fail again on resend. `runVoiceTranscription` in `studies/[id]/page.tsx` returns before it stores the recording draft.
- A local state change is fine when it is not a second announcement: `audio.ts` sets its own `limitReached` flag and a translated card line instead of showing `error.message`.
- The global side announces each error object once: `notifyUsageCapReached` in `frontend/app/services/usageCapClient.ts`, raised from the HTTP reply by `throwIfUsageCapReached` in `frontend/app/utils/apiClient.ts`.
- Regression-test through a real component catch, not the handler alone: feed a `UsageCapReachedError` and assert `toast.error` was not called (`frontend/__tests__/components/column-audio-helper.test.ts`).
- Data-engine failures are classified where they are caught and translated where they are shown (`frontend/app/utils/actionFailureMessage.ts`). Two kinds: a failed READ (opening a document, loading a list or its state error, finding drafts) carries nothing the person can act on, so `failureWords(error, fallbackKey)` says the caller's line and logs the original once per error object (`logFailureOnce`, shared with the engine provider's background report, so a failure two catches see is logged once); a refused ACTION (save, a version choice, a form, recovering a draft, and the editor's own `state.error`, which the controller also fills from refused actions) may carry an instruction, so `refusalWords` keeps an unknown refusal's own sentence, as before, until its code is translated (BUG-20261003-engine-refusals-speak-english). Both keep a refusal already written for the person (`code: 'read-only'`, or `saidError(t(...))`) in the language it was written in, and say a cause the person can act on by its code (`KNOWN`). The engine hooks (`useDataDocument`, `useDataForm`, `useDataCollection`, `useDataMembership`, `useRecoveryDiscovery`) store these words and call `sayFailure` at render, so a language switch re-says a failure said by key; the panels (`DataSyncStatus`, `DataMembershipStatus`) print what they are given. Toasts: `actionFailureMessage` / `refusalMessage`.
- Do not translate in the panel: it erases words callers already translated. Do not store a translated string in state: it freezes the language. Do not replace an unknown action refusal with a generic line: it erases instructions such as "The selected preach date is no longer available". Do not trust an error's message because of its code alone: `storageSilentError()` defaults to English. Say only what a code proves: `unauthenticated` covers both "signed out" and "another account", `use-new-copy` does not know where the record was deleted. Classify outside a `setState` updater: React may call an updater twice.
- A new engine refusal the person can act on gets a `code` at its throw site and a line in `KNOWN` plus `dataSync.failure.*` in all three locales; a screen that throws its own refusal from a `commit`/`save` updater uses `saidError`. A caller that shows a thrown error passes the error object up and formats it at the toast (`EngineCouncilCreator` → `care/council/page.tsx`). Test: `frontend/app/data-engine/__tests__/engineErrorSentence.test.tsx` (its `t` mock is bound to the language it was handed out in; a mock that reads the language at call time cannot catch a frozen translation).
- The same one-voice rule covers write refusals: the shared recovery toast from `useWriteRecovery` (`frontend/app/utils/recoverableWrite.ts`) speaks for them. A settings toggle only restores its switch (`StructurePreviewToggle.tsx`), and a modal that has already closed stays silent on a late refusal (`frontend/__tests__/components/CreateThoughtModal.test.tsx`).

## Why

- 2026-10-03: the sermon screen printed "The document is not available in the local cache" under its own translated "could not load" (BUG-20261003-engine-error-sentence-on-screen). The first fix translated in the panel and erased translated instructions; the second stored translated strings (frozen language), lost actionable membership prerequisites and logged one failure twice; the third named causes the code could not prove; the fourth and fifth replaced action refusals that carried instructions (a recovery, the editor's state error). Each was caught by the second engine's review.
- 2026-07-15: after the global handler existed, per-call catches still showed raw or generic errors, a second toast, and saved retry drafts. The cap's `error.message` is `Usage cap reached for ai`, a sentence for developers; it reached the card and a red toast on top of the handler's own message: one event, three announcements.
