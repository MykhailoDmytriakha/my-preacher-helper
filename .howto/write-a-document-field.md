# Write a document field

For an engine-owned collection, write through the public facade in `frontend/app/data-engine/react.client.tsx`: `useDataDocument.update/commit`, a pinned `useDataForm`, or `useDocumentActions` for a one-shot action. The engine owns durable intent, delivery, revisions and conflicts. Trusted server-generated edits use `frontend/app/data-engine/serverEdit.server.ts`. See `frontend/app/data-engine/README.md`.

## How

- `useDataDocument.update(current => next)` persists the latest editor value locally; `commit(current => next)` captures an explicit Save before awaiting storage. A Save resolving means local ownership, not server acceptance. Use the hook's status and `DataSyncStatus` for delivery, retry and conflict choices.
- `useDataForm(resource, slot, selection)` pins the fields and ancestor when a manual form opens. `update()` durably stages typing without sending it; `save()` submits that stage. Use `useDocumentActions().commit/create/remove` for a one-shot action on a document no screen has open.
- A compatibility consumer that must retire an exact backup uses the public `useDocumentActions.submit(resource, action)` receipt: local capture resolves the action, while `receipt.persistence` follows the whole immutable request ACK and returns the actual accepted snapshot. Do not infer persistence from connectivity or predict the accepted revision. Existing `create/commit/remove` still prove local capture only. Unknown delivery waits; terminal refusal/conflict/cancel or owner change cannot retire the backup. After restart reuse durable accepted evidence, such as confirmed dictation source IDs, rather than an abandoned page promise.
- A composed local action can capture one domain value and then fail its next capture. Keep the exact value returned by the completed public writer as that editor's retry baseline; a rendered row can still show an older value with the same ID. Retrying A -> B -> A must compare against captured B, not a stale screen A. A create retry preserves its client ID/date and patches its own already-present draft instead of creating a duplicate. This is local capture evidence, not a server ACK or a second queue. Worked regression: `frontend/__tests__/pages/sermons/structureCapture.test.tsx`.
- Compatibility outline consumers reuse `utils/outlineCapture.ts` for immediate writer handoff and per-editor input ancestry. Keep the exact base object until adopting a returned or canonical parent value. Observe committed parent identities through `observeView` in a layout effect;the returned captured value and whether its view is still current are separate facts. A stale completion may settle bookkeeping but must not roll back a newer adopted parent. PlanEditorModal intentionally pins its opening and does not follow later parent props. Only a departed editor may suppress the exact cancellation recognized by the public `isInactiveEditorError` facade;genuine storage refusal remains visible.
- Let the engine's editor and `useDataCollection().state.documents` publish submitted intent and acknowledgements. Keep `snapshots` as confirmed data; do not write an optimistic result directly into React Query or confirmed snapshots. Render `DataCollectionStatus` for list delivery and incompleteness.
- Trusted server-computed changes use `serverEdit.server.ts`, which submits an engine command on engine-owned documents. `frontend/__tests__/architecture/dataEngineBoundary.test.ts` freezes SDK, internal-module and legacy-HTTP bypass counts; the exception ledger only shrinks.
- A route that writes a value the CLIENT built (a whole array, an object from its cache) through `serverEdit.server.ts`: normalize it to the stored shape on the server — the engine validates against `resourceSchemas.ts` and refuses the whole command (`invalid-document`) for one missing required field; and if the value replaces what another device may have changed, take the client's `expected` copy and compare inside the `editOwnedDocument` mutate (it re-reads and retries), answering 409 with what is stored. Never ignore the route's answer on the client: `fetch` resolves on 409/500. Worked case: `api/sermons/[id]/audio/chunks/route.ts` + `utils/audioChunkIdentity.ts` (2026-09-28 — the audio wizard's source switch had failed silently since the engine move).

- Existing compatibility autosave using `changedFields` must retain the accepted read identity of an untouched projected field. Study-note `scriptureRefs` carry raw-list provenance in `useStudyNotesEngine`: keep the previous baseline reference when it was not submitted, and capture the submitted snapshot before awaiting. Other fields still come from the editor payload; applying baseline-plus-delta to everything can retain optional metadata omitted by a legacy restored draft. Tests: `studyNoteReferenceProvenance.test.tsx` and the restored-draft receipt page test. New screens still use the engine-owned editor above.
- A structured scripture reference's Bible, location, range and quote describe one authored meaning. `protocol.mergeFields` keeps a root `scriptureRefs/id:...` entry whole when both versions change it; unchanged/equal shortcuts and independent IDs still merge. `studyNotes` owns these structured references; group/service-order reference lists contain strings. Reuse the canonical command/rebase rule, never a screen-specific merger. Test: `scriptureReferenceMerge.test.ts`.

- A sermon outline removal can retire plan text only for the IDs and words known to that action. Capture this evidence with the pending request before a saved predecessor can be collected. Server acceptance compares the evidence with the current text and the merged outline. A blank canonical cell masks any legacy copy. If delivery order is all that is known, retain the words under the removed ID and surface them for recovery. A recovery discard is a separate exact-text decision and must refuse if the point returns. Proof in `sermonPlanTextDelivery.test.ts` and the plan cases in `sermonIntegrity.test.ts`.

For an exact action about a long tag, refer to its index on the original command side where membership is present. The server resolves the original string before testing the transformed membership. A thought also checks the row ID and creation identity. A storage digest bounds retained proof size without changing the displayed tag or history. Keep old literal evidence readable. The ordinary command byte limit still applies.

For a batch of tag edits, the ordinary command byte limit controls admission. Bound retained evidence separately with shared stamps and a storage budget. If the proof expires, keep an exact comparison. Oversized comparison receipts may refer to tags in the hash-verified original command and store the result in authenticated, integrity-checked parts. Split large displaced history into bounded records rather than cutting off the last action.

## Legacy paths (unconverted collections only)

These compatibility paths are not templates for new features.

- `conflictSafeUpdate(...)` compares the value the editor opened with (the baseline) against the server, then writes or refuses; offline it queues the intent. It bumps the aggregate's counter `rev.<aggregate>` itself.
- `revisionedUpdate` / `revisionedBatch` / `revisionBump`, the unguarded doors, were removed on 2026-10-13: their last callers went with the legacy writers.
- Never a bare `updateDoc` / `setDoc` for an own-document write: it silently drops the race check, the outbox and the typed errors. `frontend/__tests__/architecture/writesGoThroughTheInterface.test.ts` freezes the remaining direct writes per file — a number may only go down. It also counts `writeBatch` and `runTransaction`; it cannot see an aliased import.
- Per-item leaf writes (`planText.<nodeId>`): scope the check to that item's baseline, not the whole aggregate — otherwise editing two different points reports a conflict that does not exist.
- Every writer of a field moves its counter: scripts and migrations included (`frontend/scripts/migrate-plan-text.js` bumps `rev.plan`), and a second writer of the same field bumps the same revision before scheduling its write (outline Apply and the manual save both write `sermon.outline`).
- Report a legacy write as a patch of what changed; each side — list cache, detail cache, screen — merges it into the copy it owns. Never hand a whole entity across a boundary: the list copy and the detail copy differ in completeness and are not comparable (`frontend/app/hooks/useSermon.ts`, "the list copy is a fallback, not a candidate"). (Legacy path; removed 2026-10-13 — engine screens read the document instead.)

### When the legacy write is refused

- `isStaleWriteError(error)` → `error.serverValues` is what the transaction found on the server. Adopt it as the new baseline, keep the person's text on screen and still marked unsaved, and say so; a second, deliberate press then means "mine wins". A guard without this exit only moves where the text is lost.
- `OfflineQueuedError` → the intent is queued; tell the person it will be delivered.
- On a detected race show the banner, never a silent overwrite. An online save promise must reject back to the UI, so a failure shows an error and not a success toast.

## Why

- 2026-08-15: a new plan-text writer called `updateDoc` directly — the same trap had been stepped in five times, always by a new feature copying a neighbour. So the rule is structural: the guard test keeps the door shut, not the author's memory.
- 2026-08-15: `migrate-plan-text.js` first moved content without touching `rev`, so a copy cached before the move could never be proven older; the stale copy kept winning and the guard refused legitimate saves. Documents moved before the fix were retrofitted with `frontend/scripts/touch-plan-revision.js`.

### Legacy traps

- A save is refused although the value is really on the server → the screen and the refusal read different fields (legacy cells merged on read vs the raw `planText`). Judge both by the same canonical value.
- Two different points of one plan "conflict" → the baseline is aggregate-wide; scope it to the item.
