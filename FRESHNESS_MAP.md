## 7. Точный механизм потери текста (заметка) — разобран по коду

Вопреки первому впечатлению, СЕРВИС ведёт себя корректно: `studies.service.ts:143-157` перечитывает свежий документ, берёт только поля из белого списка и мержит (`{...existing, ...whitelisted}`). Поля друг друга не затирают.

**Потеря приходит СВЕРХУ, из редактора:** `studies/[id]/page.tsx:213-216` при автосохранении отправляет ВЕСЬ набор своего состояния — `{ title, content, tags, scriptureRefs, type }` — независимо от того, что человек реально менял. Правил только заголовок → тело всё равно уедет в запись, причём тем, каким оно было НА МОМЕНТ ОТКРЫТИЯ вкладки.

Усугубляет проверка «не изменилось ли» (`:200-207`): она сравнивает текущее состояние с `existingNote` — снимком, загруженным при открытии, а НЕ с тем, что сейчас в базе. Если другое устройство успело записать, вкладка об этом не знает и считает свои данные валидными.

**Вывод для плана:** лечение должно стоять НА ВХОДЕ (редактор не отправляет устаревшее состояние молча), а не в сервисе. Два рычага:
1. слать только реально изменённые поля (тогда чужие поля физически не затираются);
2. знать актуальный `updatedAt` и не писать поверх более новой версии без ведома человека.
Первый рычаг убирает БОЛЬШУЮ часть класса (правки разных полей перестают конфликтовать вовсе), второй закрывает остаток (правка ОДНОГО поля с двух устройств).

## 8. Класс шире заметки — и правильный образец УЖЕ есть в коде

Проверено по всем детальным редакторам:

| Сущность | Что отправляет при сохранении | Теряет чужие правки? |
|---|---|---|
| Заметка | `{title, content, tags, scriptureRefs, type}` — ВСЁ состояние (`studies/[id]/page.tsx:213`) | **ДА** (воспроизведено) |
| Проповедь | `{...sermon, verse}` — ВЕСЬ объект ради одного поля (`sermons/[id]/page.tsx:1155`) | **ДА** (тот же класс) |
| Серия | только `updates` (`useSeriesDetail.ts:212`) | нет |
| Группа | только `updates` (`useGroupDetail.ts:108`) | нет |
| Молитва | `Pick<'title'> & Partial<'description'|'tags'>` (`prayers/[id]/page.tsx:135`) — только изменяемые поля | нет |

**⚠️ СЧЁТ ИСПРАВЛЕН 2026-07-25 (Popper опроверг).** Правильные только ДВЕ: серия и молитва.
**Группа НЕ правильная** — `groups/[id]/page.tsx:201-208` шлёт `title/description/status/templates/flow` при любом автосейве, запись fire-and-forget (`useGroupDetail.ts:105`). Я вывел «группы правильные» из сигнатуры хука, не открыв вызывающего — ошибка «прочитал слой сервиса, достроил поведение вызывающего».
Отклонившихся точек ЧЕТЫРЕ: заметка · проповедь (title/verse/preparation) · подготовка (весь вложенный объект) · группа.

**Вывод:** правильный паттерн («шлём только изменённые поля») в приложении УЖЕ ЕСТЬ — серии, группы и молитвы так и делают. Заметка и проповедь — отклонение от него. Значит первый шаг плана не «строить механизм», а **привести отклонившиеся места к существующему образцу**: это убирает потерю при правке РАЗНЫХ полей вообще, без новой инфраструктуры.

Остаётся случай «двое правят ОДНО И ТО ЖЕ поле» — вот его закрывают уведомление о свежести + проверка версии при сохранении.
